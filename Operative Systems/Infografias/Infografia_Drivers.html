Un controlador de dispositivo (driver) es un módulo de software que actúa como intermediario entre el sistema operativo y un dispositivo de hardware. El driver traduce las solicitudes abstractas del kernel (leer datos, escribir datos) en las instrucciones específicas que el hardware entiende. En Linux, los drivers se implementan como módulos del kernel (Loadable Kernel Modules) que pueden cargarse y descargarse en tiempo de ejecución sin reiniciar el sistema [1].
Figura 1. Capas del sistema: del programa de usuario al hardware
El driver opera en espacio de kernel, traduciendo las llamadas del sistema a instrucciones de hardware [1], [2].
1 Arquitectura de un driver en Linux

El kernel de Linux organiza los drivers en tres categorías según el tipo de dispositivo que controlan [2]:

Char Device
Flujo secuencial de bytes.
Ej: teclado, mouse, serial
Block Device
Acceso aleatorio por bloques.
Ej: disco duro, SSD, USB
Network Device
Paquetes de red.
Ej: Ethernet, WiFi

Un driver de teclado USB es un char device porque transmite datos como un flujo secuencial de caracteres. En Linux, se implementa dentro del subsistema de entrada (input subsystem) y el subsistema USB (USB core) [3].

2 Estructura de un módulo del kernel

Todo driver en Linux sigue una estructura mínima con dos funciones obligatorias: una de inicialización y una de limpieza [1]:

Estructura mínima de un módulo — módulo.c
#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

static int __init mi_driver_init(void) {
  printk(KERN_INFO "Driver cargado\n");
  return 0;
}

static void __exit mi_driver_exit(void) {
  printk(KERN_INFO "Driver descargado\n");
}

module_init(mi_driver_init);
module_exit(mi_driver_exit);
MODULE_LICENSE("GPL");
Elemento Función
module_init() Registra la función de inicialización al cargar con insmod
module_exit() Registra la función de limpieza al descargar con rmmod
printk() Equivalente a printf para el kernel. Escribe en dmesg
MODULE_LICENSE() Declara la licencia (obligatorio para la API GPL del kernel)

3 Operaciones de archivo (file_operations)

En Linux, los dispositivos se acceden como archivos en /dev/. El driver define qué sucede cuando el usuario lee, escribe o abre el dispositivo [1]:

file_operations para un char device
static struct file_operations fops = {
  .owner  = THIS_MODULE,
  .open   = mi_open,  /* Al abrir /dev/mi_device */
  .read   = mi_read,  /* Al leer del dispositivo */
  .write  = mi_write, /* Al escribir */
  .release = mi_close, /* Al cerrar */
};

Cuando un programa ejecuta open("/dev/teclado", O_RDONLY), el kernel localiza el driver asociado y llama a la función .open definida en file_operations [2].

/* Dentro del callback del URB */
input_report_key(input_dev, keycode, 1); /* 1=presionada */
input_sync(input_dev);

input_report_key(input_dev, keycode, 0); /* 0=soltada */
input_sync(input_dev);
5 Compilación y carga del módulo

Los módulos del kernel se compilan con el sistema kbuild [1]:

Makefile para un módulo del kernel
obj-m += mi_driver.o

all:
  make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
  make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean
Comando Acción
make Compila el módulo (.ko)
sudo insmod mi_driver.ko Carga el módulo en el kernel
sudo rmmod mi_driver Descarga el módulo del kernel
dmesg | tail Ver mensajes del kernel (printk)
lsmod Listar módulos cargados

6 Conceptos clave en la programación de drivers

Espacio de kernel vs usuario

Los drivers se ejecutan en espacio de kernel con acceso total al hardware. Un error puede causar kernel panic. Las funciones son diferentes: kmalloc en vez de malloc, printk en vez de printf, copy_to_user para pasar datos al usuario [2].

Interrupciones (IRQ)

Cuando un dispositivo necesita atención genera una interrupción que suspende la CPU. El driver registra un handler con request_irq() que se ejecuta inmediatamente al ocurrir la interrupción [1].

DMA (Direct Memory Access)

Permite que el hardware escriba datos directamente en RAM sin intervención del CPU. El driver configura los buffers DMA y el controlador DMA del sistema para transferencias de alto rendimiento [2].

URBs (USB Request Blocks)

En drivers USB, la comunicación se realiza mediante URBs: estructuras que encapsulan una transferencia. El driver los envía con usb_submit_urb() y recibe una callback al completarse [3].
